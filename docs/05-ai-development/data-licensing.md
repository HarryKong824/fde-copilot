### 1.2 🔴 会话事件里**实测含凭据**——已实现脱敏

**发现经过**（`_inbox/0077`）：

```
session 事件里实测含凭据
  （本项目里出现过 launch token、bearer token、wbipc 票据等）
```

**已落地的脱敏实现**（`dsh-fde-memory/lib/session-audit.js`）：

```js
// 键名命中即整值替换（宁多不漏）
const REDACT_KEY_RE =
  /(token|secret|password|passwd|credential|authorization|cookie|api[_-]?key|jwt|bearer|signature)/i

// 值样式命中也被替换
out = out.replace(BEARER_RE, '[REDACTED:bearer]')
out = out.replace(SK_RE,     '[REDACTED:sk]')
out = out.replace(JWT_RE,    '[REDACTED:jwt]')
```

**三条设计说明**：

| 设计 | 说明 |
|---|---|
| **键名匹配 + 值样式匹配，双路** | 只匹配键名会漏掉「值看起来像 token 但键名正常」的情况 |
| **`[REDACTED:xxx]` 带类型后缀** | 保留「这里曾是一个 bearer token」这个事实，便于事后审计 |
| **深度上限** | 超过 `MAX_DEPTH` ⇒ `[REDACTED:depth]`（防止深层嵌套对象绕过） |

**实测验证**（`_inbox/0088`）：`maxTokens` 键名**命中** token 规则 ⇒ 被 `[REDACTED]` ⇒ **脱敏生效**。

> ⚠️ **但要注意**：**这是「宁多不漏」的保守策略**，会**误伤**（如 `maxTokens` 这种正常配置项也被脱敏）。
> 这是**有意的取舍**——审计链宁可少记一点，也不能漏凭据。

### 2.3 ✅ 自研组件（无第三方许可证问题）

| 组件 | 说明 |
|---|---|
| `yamlsubset.js` | **自研的受限 YAML 子集解析器**——为了**不引入第三方 YAML 库**而写的 |

**为什么自研**（这是设计决策，不是偷懒）：

| 理由 | 说明 |
|---|---|
| 零依赖 | 插件不能给宿主引入额外的依赖面 |
| 行为可控 | **fail-closed**：解析不了就报错，不会静默产生一个「看起来对」的结果 |

> ⚠️ **代价（必须知道）**：它是**受限子集**——**行内集合必须写合法 JSON（双引号）**：
> ```yaml
> condition: {">": [{"var": "treatment.dose_mg"}, 100]}    # ✅
> condition: {'>': [{'var': 'treatment.dose_mg'}, 100]}    # ❌ 单引号解析失败
> ```
> 这条限制已写进《用户操作手册》§5.4 与《常见问题 FAQ》A4。
