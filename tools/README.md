# `tools/` —— 独立工具脚本（**不进回归**）

这里放**不属于离线回归**的脚本：活体验证驱动、勘察探针、会话与审计读取、变异注入、
状态播种与复原、一次性核账。**共 111 个。**

它们**不参与** `tests/_run_all_tests.sh`（那个脚本只收 `_*_test.mjs`），
所以**这里的脚本坏了不会让回归变红** —— 用之前先看它自己有没有判红能力。

---

## 与 `tests/` 的分工

| 目录 | 放什么 | 自动化 |
|---|---|---|
| **`tests/`** | 41 套离线回归 + 它们**真正依赖**的 7 个脚本 | ✅ 每次跑、有汇总判定 |
| **`tools/`** | 一次性 / 需要真环境 / 手动跑的脚本 | ❌ 手动，**不判红** |

> 🔴 **别拿这里的脚本当判据。** 它们大多是"给人看的"（打印观测结果），
> 不是"给门禁判的"。本项目的规矩是：**观测与判定必须分开**
> （同类教训见 `tests/_tool_surface_check.mjs` 的注释：它专门单开一个文件，就是为了不当"看着像判红"的那种）。

## 大致分几类（按名字模式，**有重叠、不是精确划分**）

| 类别 | 匹配模式 | 数量 | 干什么 |
|---|---|---|---|
| **活体验证** | `*_live*` / `*_drive*` | 17 | 驱动真 DSH 跑一遍并收证据（多数要 DSH 在跑） |
| **勘察探针** | `*probe*` | 22 | 探平台行为：锁、guard、restrict、transcript、preset、工具面 |
| **读取/查看** | `*_peek*` / `*_dump*` / `*_scan*` / `*_header*` / `*_tail` | 16 | 读会话、读事件、读工具面快照 |
| **变异注入** | `*_mut` / `*_mutate*` | 7 | 故意改坏源码，验证套件会不会报警 |
| **状态播种/复原** | `*_seed*` / `*_patch*` / `*_restore*` | 11 | 造出要验的状态，跑完再复原 |
| **一次性核账** | `*_verify*` | 10 | 核对某件事到底做没做（多为历史工单） |

**合计 111 个**（各类**有重叠**：一个脚本可能既匹配 `*probe*` 又匹配 `*live*`，所以上表相加会大于 111）。

> ⚠️ **数这类计数别用 `ls A B | wc -l`** —— 两个 glob 命中同一个文件时 `ls` 会**把它打印两次**，
> 实测「活体验证」这样量出来是 **21**，去重后才是 **17**。正确写法：`ls A B | sort -u | wc -l`。

## 路径约定

本目录与 `tests/` **同级**、都在仓库根下一层，所以：

- 引用插件代码一律用 `'../dsh-fde-*/lib/*.js'`。
- **实测**：本目录 **17 个**脚本这样引用、**0 个**还用旧的 `'./dsh-fde-*'`。
  （2026-09-29 从仓库根搬来时已批量改写；`tests/` 同款改写见那边的 README。）

## ⚠️ 用之前先知道的几件事

| 事项 | 说明 |
|---|---|
| **有的要 DSH 在跑** | 设 `FDE_DSH_HOME=<你的 dsh-home>`；没有那份部署时它们多半直接失败**而不是跳过** |
| **有的要 launch token** | 每次启动 DSH 都会变，得由人提供 |
| **`_restart_dsh.mjs` 会动正在运行的 DSH** | 它 `process.kill` 掉 Electron + 后端进程再拉起 —— **别随手跑**，它会把当前会话的 DSH 重启掉 |
| **`_seed_*` / `_patch_*` / `_restore_*` 会改真实状态** | 它们写的是 `<projectRoot>/memory/` 下的真文件。**跑之前想清楚最坏结果**，跑完按脚本自带的复原步骤还原（注意：复原时**别手改 `revision`/`updated_at`**，那是计数器/时间戳，手改等于伪造） |

## 想找某个脚本

用名字找即可 —— 命名规则是 `_<主题>_<动作>.mjs`，例如：

- 想知道"锁会不会被强夺" → `_lock_probe.mjs`、`_lock_probe_live.mjs`、`_lock_holder_sim.mjs`
- 想知道"审计链断没断" → **用现成的 `_replay_phase_audit.mjs`，别自造 one-liner**：
  `node tools/_replay_phase_audit.mjs [路径]` 只读逐行校验 `phase.jsonl` 的 seq 连续性、
  `hash`/`prevHash` 接续、restrict 记录齐全；结果写 `_replay_phase_audit_out.txt`，
  `exit 0` = 链完整。
  **实测（2026-09-29，默认路径）**：`断链 0 处` / `RESULT: CHAIN-INTACT` / `EXIT=0`。
  （不传路径时默认读本机 `dsh-home/fde-audit/phase.jsonl`。）
- 想核对某份历史工单 → `_verify_00XX.mjs`、`_count_0090_status.mjs`
